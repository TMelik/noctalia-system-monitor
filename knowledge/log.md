# Knowledge log

- **2026-08-24 — Initialization:** Added the compact Google OKF v0.2 knowledge bundle, source-backed concepts, privacy boundary, current-state handoff, and local validator.
- **2026-08-24 — Presentation:** Grouped processor, memory, storage, and network metrics with subtle separators while retaining one compact capsule.
- **2026-08-24 — Settings:** Released the local 1.1.0 manifest with independent metric visibility, separator and tooltip toggles, network-unit style, configurable disk path, and a distinct `server-2` RAM glyph.
- **2026-08-24 — Licensing:** Selected GPL-3.0-only for the public plugin and added the standard license text.
- **2026-08-24 — Rename:** Renamed the public plugin to System Monitor with canonical id `tmelik/system-monitor` before community-store submission.
- **2026-08-24 — Publication media:** Replaced the standalone bar crop and synthetic card with an official-generator thumbnail based on a privacy-clean Noctalia System capture, then submitted the package in community PR #460.
- **2026-08-25 — Extended monitoring:** Implemented and locally validated version 1.3.0/API 26 with optional GPU metrics, global-threshold highlighting, exact-interface networking, unavailable-value hiding, absolute RAM/disk modes, detailed rendered-metric tooltips, and synchronized public/OKF documentation.
- **2026-08-25 — Structured tooltip:** Replaced the normal multiline text with Noctalia's ordered two-column tooltip rows, combined percentage with used/total amounts, retained rendered-metric filtering, and kept fallback strings unchanged.
- **2026-08-25 — Tooltip width:** Shortened the aggregate network key from `Network (Total)` to `Network` and applied the existing compact-unit setting to tooltip rates, preserving selected-interface identification while preventing RX/TX clipping.
- **2026-08-26 — Network session totals:** Replaced duplicate tooltip rates with in-memory RX/TX estimates integrated once per new Noctalia sample; documented that counters reset with the plugin runtime and are not system-uptime totals.
- **2026-08-26 — Top processes:** Prepared version 1.4.0 with a declared `ps` dependency, default-enabled Top CPU/RAM tooltip rows, five-second asynchronous polling, CPU-time delta sampling, RSS reporting, and a documented process-metadata trust boundary.
- **2026-08-26 — Top-process visibility fix:** Split the process poll into a two-stage query (a namesless numeric snapshot across all visible processes for CPU/RAM candidate selection, then a short `comm` lookup only for the winning PIDs) so Top CPU/RAM populate reliably instead of being cut off by the runtime output cap; removed the temporary debug instrumentation used to diagnose it.
- **2026-08-26 — Opt-in CPU tooltip, GPU auto-detect, frequency fallback:** Released version 1.5.0. CPU usage/temperature/frequency/load in the tooltip are now opt-in via `show_cpu_details_in_tooltip` (default off) since the capsule already shows enabled CPU metrics. GPU usage/temperature/VRAM became per-field `auto`/`on`/`off` selects (default `auto`), auto-showing only when a GPU actually reports that field instead of a static always-off default. Added a declared `cat` dependency for a CPU-frequency fallback (sysfs `scaling_cur_freq`, then `/proc/cpuinfo`) used only when Noctalia doesn't report `cpu.freqMhz` itself.
- **2026-08-26 — Highlighting investigated, kept two-tier:** Briefly removed the "activity" color tier at user request after a perceived color-consistency issue; pixel-level testing (including with highlighting fully disabled) showed the perceived dimness came from Noctalia's own Tokyo-Night theme rendering, not plugin code, so the two-tier activity/critical highlighting and `activity_color` setting were restored. Verified with a throwaway Lua 5.1 mock harness capturing actual rendered colors across threshold boundaries.
- **2026-08-26 — Retained metric color fix:** Released version 1.5.1 after a deeper host-reconciler review corrected the earlier theme-only diagnosis. Metric glyphs, labels, and dividers now have stable declarative UI keys, and normal values explicitly restore `on_surface`, preventing auto-detected GPU rows or falling thresholds from retaining divider/activity colors. A throwaway Lua 5.1 regression mock covered GPU insertion, VRAM/RAM colors, unique keys, and critical-to-normal reset.
